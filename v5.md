## 1. Executive Summary & Root-Cause Analysis

A comprehensive audit of the v3.0 codebase revealed that while foundational components (Alembic migrations, Redis rate limiting, G&SR audit logging, frontend code splitting) were implemented, critical architectural seams were left unresolved:

1. **Broken Optimization Contract**: Changing `POST /api/v1/optimize/run` to return `202 Accepted` broke `backend/scripts/demo_driver.py` (which crashed with `KeyError: 'metrics'`) and left the frontend metrics display unpopulated because `frontend/src/services/api.ts` never implemented polling.
2. **Orphaned Hero Components**: `frontend/src/components/YardInterlockingSchematic.tsx` (281 lines of 4-aspect SVG interlocking schematic code) was written but never imported or mounted on any page.
3. **Disconnected Telemetry Stubs**: `track_recording_car_parser.py` and `cris_coa_adapter.py` existed only as isolated files without live API endpoints or ML pipeline integration.
4. **Coarse Track Physics**: Sections remained coarse 82 km station-to-station edges rather than genuine 1.0 km Automatic Block Signalling (ABS) track circuits.

This document itemizes the **Immediate Critical Edits (Phase 1)** and the **Deep Architectural Advancements (Phase 2)** required to achieve full production readiness.

### Detailed Fix Specifications:

#### FIX-01: Dual-Mode Optimization Endpoint (`backend/api/routes/optimization.py`)
* **Problem**: Pure async 202 breaks automated test drivers, curl requests, and client components that require synchronous results.
* **Fix**:
  ```python
  @router.post("/run")
  async def run_optimization(
      payload: OptimizationTriggerRequest,
      background_tasks: BackgroundTasks,
      sync: bool = Query(False, description="Run synchronously and return metrics immediately"),
      current_user: dict = Depends(require_division_access),
      db: Session = Depends(get_db)
  ):
      if sync:
          # Run synchronously and return {status: "SUCCESS", metrics: {...}, blocks: [...]}
          result = execute_synchronous_optimization(...)
          return result
      # Else return 202 Accepted with task_id
      return {"status": "ACCEPTED", "task_id": task_id, "poll_url": f"/api/v1/optimize/run/{task_id}/status"}
  ```

#### FIX-02: Update Demo Driver Script (`backend/scripts/demo_driver.py`)
* **Problem**: Script fails on Step 2 with `KeyError: 'metrics'`.
* **Fix**: Call `requests.post(f"{BASE_URL}/api/v1/optimize/run?sync=true", json=payload)` or implement 5-second polling loop until `task_status == "COMPLETED"`.

#### FIX-03: Mount `YardInterlockingSchematic` in `DivisionalControlCockpit.tsx`
* **Problem**: SVG yard schematic is invisible.
* **Fix**: Add a tabbed interface or prominent section in `DivisionalControlCockpit.tsx`:

  - Tab 2: **Junction Yard Interlocking Schematic (SVG)** (Station view with 4-aspect signal heads for GZB / ALJN).

#### FIX-04: Wire Real Telemetry Ingestion Endpoints
* **Problem**: `track_recording_car_parser.py` is never called by the API.
* **Fix**:
  - Implement `POST /api/v1/telemetry/upload-tg4`: Accepts IRPWM OMS-2000 / TG-4 CSV uploads, parses TGI standard deviations, updates `sections.track_geometry_index`, and dynamically recalculates XGBoost risk scores.
  - Implement `GET /api/v1/integrations/coa/active-trains`: Streams live timetabled train status from the CRIS COA adapter.

### 3.1 Sub-Kilometer Signal Block-Headway Model (ABS & Interlocking Turnouts)
* **Target Files**: `backend/optimization/cpsat_optimizer.py`, `backend/database/models.py`
* **Engineering Specification**:
  - Quadruple-line track (UP Fast, UP Slow, DN Fast, DN Slow) discretized into **1.0 km Automatic Block Signalling (ABS)** track circuits.
  - When track work occurs at KM 44.0–46.0 on UP Fast:
    1. Solver isolates only track circuits `TC_44_UP` and `TC_45_UP`.
    2. Approaching trains receive Double Yellow at KM 42 and Yellow at KM 43.
    3. Solver evaluates crossover turnout switches: If turnout switch at KM 42 is clear, divert train onto `UP_SLOW`, allowing continuous traffic without stopping.

### 3.2 Live RTIS NavIC Satellite Telemetry Streaming Ingester
* **Target Files**: `backend/integrations/rtis_stream.py`, `backend/optimization/simulation.py`
* **Engineering Specification**:
  - Ingests ISRO NavIC satellite transponder packets transmitted every 30 seconds by WAP-7 and Vande Bharat locomotives.
  - Computes dynamic arrival drift $\Delta t$ at station boundaries:
    $$\Delta t = t_{\text{estimated}} - t_{\text{timetabled}}$$
  - If $\Delta t \ge 10\text{ minutes}$, trigger automated solver hot-restart to re-allocate the vacated corridor capacity for routine maintenance.

### 3.3 Automated Kavach (TCAS) Digital Braking Envelopes
* **Target Files**: `backend/integrations/kavach_adapter.py`, `backend/api/routes/blocks.py`
* **Engineering Specification**:
  - Under RDSO Specification `RDSO/SPN/196`, block closures must broadcast electronic Movement Authority constraints.
  - Automatically compiles **Kavach Packet 51 (Temporary Speed Restriction)** and **Packet 65 (Virtual Red Signal)**.
  - Generates geofenced braking curves: Enforces automated locomotive brake application if a train approaches within 1,200 meters of an active maintenance block.

### 3.4 PKI / X.509 Hardware Token Signatures for Legal G&SR Handshakes
* **Target Files**: `backend/core/pki_signer.py`, `backend/api/routes/blocks.py`
* **Engineering Specification**:
  - Replaces raw database SHA-256 strings with **X.509 Digital Signature Certificates (DSC)**.
  - Station Master Form T/351 Disconnection Memos and TPC 25kV OHE isolation PTWs signed using PKCS#7 / CMS format.
  - Generates judicial inquiry evidence packets (`GET /api/v1/blocks/{id}/crs-audit-packet`) containing verified digital signature chains admissible before the Commissioner of Railway Safety (CRS).

### 3.5 Continuous Online MLOps Pipeline on Real Track Car Data
* **Target Files**: `backend/ml/continuous_learner.py`, `backend/ml/train_risk_model.py`
* **Engineering Specification**:
  - Automatically retrains XGBoost failure risk models whenever new OMS-2000 / TG-4 track car CSVs are ingested.
  - Implements **Champion-Challenger validation**: Challenger model is only promoted if validation $R^2 \ge 0.95$ and mean absolute error decreases.
  - Monitors Kolmogorov-Smirnov distribution drift on Track Geometry Index (TGI) standard deviations.

### 3.6 Offline-First Progressive Web App (PWA) for Field Gangmen
* **Target Files**: `frontend/src/services/offline_store.ts`, `frontend/public/manifest.json`
* **Engineering Specification**:
  - Enables track maintainers (Keymen and Gangmen) to record track defects in remote rural areas without 4G/5G connectivity.
  - Implements `localforage` (IndexedDB) offline queue.
  - Captures device hardware GPS coordinates and WebP-compressed camera photos of rail cracks.
  - Triggers Background Sync API (`sync-field-tickets`) upon reconnecting to cellular networks.

### 3.7 Pan-India Multi-Zonal Tenancy (17 Zones, 68 Divisions)
* **Target Files**: `backend/database/tenancy.py`, `backend/api/routes/corridor.py`
* **Engineering Specification**:
  - Implements PostgreSQL **Row-Level Security (RLS)** scoped by `division_id` and `zone_id`.
  - Enforces tenant isolation: Delhi Division controllers cannot alter Prayagraj Division blocks without mutual inter-divisional concurrence.
  - Railway Board portal (`/board`) receives real-time aggregated KPIs across all 17 Zonal Railways via Redis pub/sub.

### 3.8 Automated Chaos Engineering & Disaster Recovery Suite
* **Target Files**: `backend/tests/chaos/test_chaos_recovery.py`
* **Engineering Specification**:
  - Injects simultaneous compound disruptions: 3 emergency rail fractures + 2 OHE wire snaps + complete signaling circuit power loss.
  - Asserts fail-safe invariants: Zero train collisions, automatic loop line holding, and solver convergence within 10.0 seconds.

## 5. Engineering Directives for Implementing Agents

1. **Maintain Backward Compatibility**: Never break existing API response schemas without providing query parameters (e.g., `?sync=true`) or graceful fallbacks.
2. **Mount All Visual Deliverables**: Never leave UI components orphaned in `src/components/`. Every component must have a clear route or container integration.
3. **Verify Full System Integration**: A unit test passing in isolation is not proof of feature completion. Always verify against `demo_driver.py` and the live React interface.
4. **Adhere to Statutory Railway Rules**: Safety state transitions must strictly preserve the legal lifecycle: `PLANNED → SANCTIONED → DISCONNECTED → PTW_GRANTED → FIT_RESTORED`.
